# FSK 피트보드

FSK(Formula Student Korea) 차량 제작동아리용 팀 현황판입니다. 부품 제작 진행, 주행 테스트, 대회 일정, 사비 정산을 한 페이지에서 30명 안팎의 팀원이 함께 씁니다.

같은 `index.html`이 두 곳에서 돌아갑니다.

- **자체 서버 (라즈베리파이 등, 최종 운영용):** `server/` 의 Node.js 서버가 로그인, 데이터베이스(SQLite), 실시간 동기화, 첨부 파일, 권한을 맡고, 개발자 전용 관리 창(`/admin`)을 제공해요. 설치는 [deploy/RASPBERRY_PI.md](deploy/RASPBERRY_PI.md).
- **claude.ai Artifact (지금 쓰는 곳):** 데이터는 Artifact의 공유 데이터베이스와 파일 저장소에 있어요.

이 저장소에는 코드와 설정만 있고 팀 데이터는 없습니다.

## 빠른 시작 (자체 서버)

```bash
# Node.js 22.13 이상, 설치할 패키지 없음
npm start                    # http://127.0.0.1:8080 , 데이터는 ./data
npm test                     # 서버 API · 사비 양식 규칙 · 모듈 테스트
npm run test:e2e             # 브라우저 테스트 (Playwright가 있을 때만, 없으면 건너뜀)
```

처음 가입하는 사람이 개발자 계정이 되고, 이후 가입은 개발자가 승인해요. 팀원은 가입할 때 부서를 꼭 골라야 해요. 관리 창이나 `npm run admin -- create-user`로 계정을 만들 때도 부서가 필요해요(개발자 계정만 생략 가능). 이름과 부서는 그 뒤로 개발자만 `/admin` 사용자 탭에서 바꿀 수 있고(승인 대기 중에도 가능), 바꾸면 그 사람이 열어 둔 화면에 바로 반영돼요. 환경 변수: `PORT`(8080), `HOST`(127.0.0.1), `DATA_DIR`(./data), `TRUST_PROXY`(터널 뒤에서 1), `COOKIE_SECURE`, `TZ`(알림·백업 시각 기준, 예: `Asia/Seoul`), `WEBHOOK_HOSTS`(Discord·Slack 말고 알림을 보낼 서버 주소, 쉼표로 구분).

조직과 권한:

| 구분 | 누구 | 할 수 있는 일 |
|---|---|---|
| 개발자 | 개발자 권한을 받은 사람 | 모든 데이터 쓰기, 관리 창, 사비 정산 완전 삭제 |
| 임원진 | 팀장 · 부팀장 · 파트장(부서마다) | 팀원 권한 + 차량 설정, 출주 전 점검 항목, 일정 관리 |
| 총무 | 부팀장이 겸직 | 임원진 권한 + 사비 정산 지급 처리·수정본 교체·삭제·대리 등록 |
| 팀원 | 직책 없는 사람 | 부품·테스트 세션·부서 기록 작성, 사비 내역서 제출, 첨부 파일 올리기 |

- 팀장·부팀장은 한 명, 파트장은 부서마다 한 명이에요. 새로 지정하면 이전 사람은 자동으로 팀원이 돼요.
- 개발자도 직책을 겸할 수 있어요 (예: 개발자이면서 부팀장이면 총무 업무도 함).
- **부품 잠금:** 그 부서 파트장과 팀장·부팀장·개발자는 부품 창에서 부품을 잠글 수 있어요. 잠긴 부품은 이 사람들만 고치거나 지우거나 잠금을 풀 수 있고, 누가 언제 잠갔는지 서버가 기록해요.
- 마지막 개발자 계정은 개발자 권한을 빼거나 비활성화할 수 없어요. 웹 관리 창에 들어갈 수 없을 때는 `npm run admin -- reset-password <아이디>` 같은 명령으로 복구해요.

## 알림 (자체 서버)

오른쪽 위 **알림**에 개인 알림이 모이고, 페이지를 열어 둔 동안에는 바로 떠요.

| 무엇 | 누구에게 |
|---|---|
| 사비 정산 보완 요청 · 승인 · 지급 완료 · 반려 (총무 메모, 지급액 포함) | 제출한 사람 |
| 새 사비 내역서 | 총무(부팀장). 부팀장이 없으면 개발자 |
| 내 부서 기록에 달린 의견 | 기록을 쓴 사람, 앞서 의견을 단 사람 |
| 부품 마감 D-3 이내 · 오늘 · 지남 | 부품의 담당(목록에서 고른 계정, 예전에 이름만 적은 부품은 이름이 같은 계정), 아니면 그 부서 파트장 |
| 일정 D-7 · D-1 · 당일 | 모두 (담당 부서가 있으면 그 부서) |
| 가입 승인 요청 | 개발자 |

알림을 누르면 해당 내역서·세션·부품으로 바로 가요. 같은 알림은 한 번만 오고, 마감·일정 알림은 아침 8시 이후에 와요(서버 시간 기준, `TZ`). 60일 지난 알림은 지워요.

관리 창 → 설정 → 알림에 **Discord 또는 Slack 웹훅 주소**를 넣으면 팀 채널로도 보내요: 일정 D-7·D-1·당일, 마감 지난 부품 하루 요약, 테스트 주의·문제 판정. 돈과 관련된 알림은 채널로 보내지 않아요.

## 휴대폰 · 앱 설치 · 오프라인 (자체 서버)

- 휴대폰 화면에 맞춰 입력 칸이 커지고(아이폰 확대 방지), 대화 상자는 전체 화면에 저장 버튼이 항상 아래에 보여요. 출주 전 점검 체크 칸도 손가락으로 누르기 쉽게 커져요.
- HTTPS 주소(Cloudflare Tunnel)로 열면 **홈 화면에 추가**해서 앱처럼 쓸 수 있어요.
- **신호가 약한 곳에서도 써요.** 한 번 연 기기는 인터넷이 끊겨도 마지막으로 본 내용으로 열려요. 끊긴 동안 바꾼 점검 체크·기록·부품은 이 기기에 저장해 두었다가(오른쪽 위 "오프라인 · 저장 대기 N") 연결되면 순서대로 올려요. 그 사이 권한이 바뀌었거나 지워진 항목은 올라가지 않고 알려 줘요. 첨부 파일과 사비 내역서는 연결된 뒤에 올려요.
- 로그아웃하면 이 기기에 저장한 데이터를 지워요. 같은 기기를 여러 사람이 쓰면 꼭 로그아웃하세요.

## 사비 정산

### 양식 자동 검사

동아리 양식 `개인사비사용내역서_이름_날짜.xlsx`를 브라우저에서 바로 읽어 검사합니다(JSZip, 엑셀·한셀 저장 파일 모두 지원).

- `내역서`·`영수증` 시트, 2행 머리글(B2:K2)
- 각 항목: 필수 칸, 팀명·구분이 양식의 숨김 목록 값인지, 날짜, 단가·수량 숫자, 합계 = 단가 × 수량
- 총 합계(K13), 계좌번호(H13) 자릿수·은행명
- 영수증 사진 유무와 구매 건수 대비 장수
- 배송비 구분, 구매처 링크·주소, 파일명 규칙, 같은 파일 중복 제출

결과는 `양식 통과` / `확인 필요` / `양식 불일치` 세 단계이며, 팀원은 양식 불일치 파일을 제출할 수 없습니다.

### 지급 상태

`검토 대기` → `보완 요청` / `승인 · 지급 대기` → `지급 완료` / `반려`

### 제출 후 잠금 (자체 서버)

자체 서버에서는 제출한 내역서를 제출자가 고치거나 지울 수 없어요. 서버가 거절해요. 바꿀 내용이 있으면 총무가 **수정본으로 교체**하거나, 새로 제출해요. 원본 파일과 영수증 사진은 제출자, 총무, 개발자만 열 수 있어요. 다른 팀원에게는 목록과 금액만 보이고 "영수증은 제출자와 총무만 볼 수 있어요"라고 나와요. 총무의 처리(상태 변경·삭제·복구·수정본 교체)는 관리 창 감사 로그에도 남아요.

### 권한

| | 팀원 | 총무 | 개발자(소유자) |
|---|---|---|---|
| 내역서 제출 | ✅ (설정으로 끌 수 있음) | ✅ (대리 등록 포함) | ✅ |
| 지급 상태 변경, 수정본 교체 | ❌ | ✅ | ✅ |
| 전체 계좌번호 보기, 원본 내려받기 | 본인 것만 내려받기 | ✅ | ✅ |
| 삭제(목록에서 숨김)·복구 | ❌ | ✅ | ✅ |
| 완전 삭제(데이터·파일) | ❌ | ❌ | ✅ |
| 총무 지정 | ❌ | ❌ | ✅ |

권한은 서버의 데이터베이스 규칙(`artifact.config.json`)으로 보호됩니다.

- 각 사람은 자기 영역(`expenses/<id>`, `reviews/<id>`, `people/<id>`)에만 쓸 수 있습니다.
- `config/roles`(총무 목록)는 소유자만 쓸 수 있습니다.
- 지급 상태는 `reviews/<id>`에 기록되며, 페이지는 총무 목록에 있는 사람(과 소유자)의 기록만 인정합니다.

알려진 한계 (claude.ai Artifact에서 쓸 때):

- 제출자는 자기 영역에 있는 제출 내용을 기술적으로 바꿀 수 있습니다. 총무 검토 뒤 내용이 바뀌면 "검토 후 변경됨"으로 표시됩니다. 자체 서버에서는 서버가 막아요.
- 화면 이름은 각자 입력한 이름입니다. 권한은 이름이 아니라 claude.ai 계정 기준입니다.
- 변경 이력은 누구나 쓰고 지울 수 있고, 부품 잠금은 화면에서만 지켜져요(소유자·편집자만 잠그고 풀 수 있게 보이지만 저장소가 막지는 않아요). 자체 서버에서는 서버가 작성자를 기록하고 이력 수정·삭제와 잠긴 부품 수정을 막아요.
- 원본 xlsx는 지원 형식 제한 때문에 base64 텍스트로 저장됩니다. 페이지를 열 수 있는 사람에게서 완전히 숨겨지지는 않습니다. 자체 서버에서는 제출자·총무·개발자만 열 수 있어요.

`index.html` 은 `<!doctype>`·`<head>` 없이 본문만 있어요. claude.ai는 게시할 때, 자체 서버는 보낼 때 문서 틀로 감싸요. 자체 서버는 이때 로그인한 계정 정보와 `fsk-runtime.js` 를 함께 넣어서, 페이지 코드를 고치지 않고도 같은 데이터 API·권한·실시간 동기화가 동작해요.

## 보안 (자체 서버)

- 비밀번호는 scrypt로 해시, 세션은 HttpOnly·SameSite 쿠키 (30일), HTTPS 뒤에서는 Secure + HSTS
- 쓰기 요청은 같은 출처 + 전용 헤더가 있어야 처리 (CSRF 방지)
- 로그인 실패 제한: IP당 15분 10회, 계정당 15분 30회. 가입 신청은 IP당 한 시간 10회. 실패도 감사 로그에 기록
- 페이지 CSP: 요청마다 새 nonce가 붙은 스크립트만 실행. 첨부 파일은 로그인한 사람에게만, 샌드박스 헤더로 제공
- 사비 내역서 원본·영수증은 제출자·총무·개발자만, 제출한 내역서는 제출자가 고칠 수 없음
- 업로드는 허용한 형식만, 파일 내용이 형식과 맞아야 받음 (확장자만 바꾼 실행 파일 거절). 파일은 확장자 없는 무작위 id로 저장하고 형식 추측 금지(`nosniff`)·실행 금지(CSP `sandbox`)로 제공. 사비 원본은 항상 `.xlsx` 이름으로 내려받음
- 권한은 `artifact.config.json` 규칙 + 계정 역할로 서버에서 검사
- 데이터 폴더 700, DB·백업·첨부 파일 600 권한

검토 결과와 남은 위험은 [SECURITY.md](SECURITY.md)에 있어요.
